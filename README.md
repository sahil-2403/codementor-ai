# CodeMentor AI

CodeMentor AI is a full-stack MERN learning platform for structured coding practice. It connects account onboarding, roadmap generation, lessons, deterministic quizzes, revision planning, projects, interview practice, progress reporting, and optional Gemini-assisted guidance in one workflow.

The first complete learning path is MERN-focused. The data model and admin CMS support additional coding paths without changing the learner workflow.

## Product principles

- **The server owns learning state.** Onboarding, active roadmaps, unlocks, attempts, scores, weak topics, revisions, and content status are persisted in MongoDB.
- **Deterministic features remain available without AI.** Authentication, onboarding, template roadmaps, lessons, quizzes, projects, interview attempts, progress, and admin content management do not require Gemini.
- **AI output is labelled honestly.** Gemini-generated reviews may include scores and weak-topic signals. Provider failures return stored course/checklist guidance without pretending it was generated by AI.
- **Writes are protected.** The API uses HTTP-only authentication cookies, refresh-token rotation, CSRF protection, request validation, rate limits, and role checks.
- **Content follows a controlled lifecycle.** Admin content moves from draft to published to archived. Publishing requires explicit confirmation and backend validation.

## Main capabilities

### Learners

- Secure registration, email verification, login, password reset, and session invalidation
- Goal and level selection with server-owned onboarding recovery
- Beginner preference-based setup and optional diagnostics for higher levels
- Versioned template or assessment-personalized roadmaps
- Ordered modules, lesson locking, completion, and module quizzes
- Deterministic quiz scoring and weak-topic/revision updates
- Contextual Gemini mentor with saved course explanations when Gemini is unavailable
- Two-attempt project tasks with optional Gemini review
- Two-attempt interview questions with expected answers unlocked after the first saved attempt
- Dashboard metrics, recommendations, revision actions, progress views, and weekly summaries

### Administrators

The admin area is intentionally limited to learning-content management:

- Topics
- Lessons
- Quiz and assessment questions
- Interview-practice questions
- Roadmap templates

It does not include user management, billing, email operations, AI-usage dashboards, queue dashboards, or fabricated platform analytics.

## Technology

### Frontend

- React 18 and Vite 5
- React Router 6
- TanStack Query
- Axios with cookie, CSRF, and refresh handling
- React Hook Form and Zod
- Tailwind CSS
- Node's built-in test runner for frontend contract tests

### Backend

- Node.js and Express
- MongoDB and Mongoose
- JWT access/refresh tokens stored in HTTP-only cookies
- Nodemailer-compatible SMTP delivery
- Optional Gemini integration
- Optional Redis cache and BullMQ workers

## Quick start

### Prerequisites

- Node.js 18 or newer
- npm
- MongoDB locally or through MongoDB Atlas
- Optional: Redis for distributed cache and BullMQ workers
- Optional: an SMTP account for real verification/reset emails
- Optional: a Gemini API key for AI-assisted features

### 1. Start the backend

```bash
cd backend
cp .env.example .env
npm install
npm run seed
npm run dev
```

The API listens on `http://localhost:5000` by default.

> **Seed warning:** `npm run seed` clears the application's seeded collections before recreating demo content. Do not run it against a database containing data you need to keep.

Health endpoints:

- `GET http://localhost:5000/health` — process liveness
- `GET http://localhost:5000/health/ready` — dependency readiness

### 2. Start the frontend

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

The frontend listens on `http://localhost:5173` by default and calls `http://localhost:5000/api` unless `VITE_API_BASE_URL` is changed.

## Optional services

### Gemini

Gemini is disabled by default. To enable it in `backend/.env`:

```env
ENABLE_AI=true
GEMINI_API_KEY=your_key
GEMINI_MODEL=gemini-1.5-flash
```

AI-assisted features include roadmap adjustment, mentor answers, quiz explanations, project reviews, interview feedback, and weekly summaries. Each feature has a deterministic or stored-content fallback. A fallback review is scoreless and does not create AI-derived weak-topic signals.

### Email

For local development, `ALLOW_DEV_EMAIL_LOG=true` allows verification/reset links to be written to the server log when delivery is disabled. For real delivery, configure the SMTP variables and set:

```env
EMAIL_ENABLED=true
ALLOW_DEV_EMAIL_LOG=false
```

### Cache and queues

The default cache driver is memory. Redis is required for distributed caching or queue workers.

Keep `ENABLE_QUEUE=false` unless Redis is available and the worker process is running. With queues enabled, start a second backend process:

```bash
cd backend
npm run worker
```

The worker entry point can start roadmap, weekly-report, and embedding workers. With queues disabled, supported flows use their synchronous path or safe fallback.

## Tests and builds

### Backend

```bash
cd backend
npm test
npm run check:gemini   # requires Gemini configuration
```

### Frontend

```bash
cd frontend
npm test
npm run build
```

The frontend test suite checks critical auth, onboarding, cache-invalidation, fallback, attempt, admin lifecycle, enum-alignment, and dead-code contracts without additional testing packages.

## Data migrations

Run migrations intentionally against the target environment and back up production data first:

```bash
cd backend
npm run migrate:attempt-numbers
npm run migrate:attempt-indexes
npm run migrate:roadmap-indexes
```

The attempt and roadmap migrations support the unique indexes used for atomic attempt limits and idempotent roadmap generation.

## Environment configuration

Start from the checked-in examples:

- [`backend/.env.example`](backend/.env.example)
- [`frontend/.env.example`](frontend/.env.example)

Important production groups include:

- Origins and proxy trust: `CLIENT_URL`, `ALLOWED_ORIGINS`, `TRUST_PROXY`
- Authentication: JWT secrets/expiry and cookie security settings
- Persistence: `MONGO_URI`, optional transaction support
- Cache/queue: `CACHE_DRIVER`, `REDIS_URL`, `ENABLE_QUEUE`
- AI: `ENABLE_AI`, Gemini key/model, timeouts, feature limits, and input limits
- Email: SMTP settings and sender addresses
- Frontend API: `VITE_API_BASE_URL`

Never commit real secrets or production `.env` files.

## Deployment notes

- Serve the frontend and API over HTTPS.
- Use `COOKIE_SECURE=true` in production and choose `COOKIE_SAME_SITE`/`COOKIE_DOMAIN` for the actual deployment topology.
- Set exact production origins; do not use wildcard credentialed CORS.
- Set `TRUST_PROXY` correctly behind a load balancer or reverse proxy.
- Use strong, independent JWT access and refresh secrets.
- Use Redis and a separately supervised worker process before enabling queues.
- Run readiness checks, migrations, backend tests, frontend tests, and the frontend production build before release.
